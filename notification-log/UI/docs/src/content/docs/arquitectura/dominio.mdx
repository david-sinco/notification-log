## La prueba está en el .csproj

`NotificationLog.NotificationService.Domain.csproj` no referencia Entity Framework, ni FluentValidation, ni ASP.NET, ni Protobuf, ni Wolverine. Solo el SDK base de .NET. Eso no es una convención de nombres de carpeta — es una regla verificable en segundos abriendo el archivo:

```csharp title="NotificationService.Domain.csproj (completo)"
<Project Sdk="Microsoft.NET.Sdk">

    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>

</Project>
```

## Cuatro agregados, no un "God Aggregate"

El dominio modela cuatro conceptos como agregados independientes, cada uno con su propia raíz, su propio repositorio y su propia invariante que proteger. Ninguno conoce a los otros tres directamente — se relacionan solo por identificador (`Guid`), nunca por referencia de objeto:

### NotificationTrigger: la invariante real del sistema

Es el agregado más rico. Su regla de negocio — "no puede haber dos configuraciones activas del mismo canal" — se protege enteramente dentro del agregado, nunca en un handler de aplicación:

```csharp title="Domain/Triggers/NotificationTrigger.cs (extracto)"
public NotificationConfiguration AddConfiguration(Guid templateId, NotificationChannel channel)
{
    EnsureChannelIsFree(channel);
    var configuration = NotificationConfiguration.Create(templateId, channel);
    _configurations.Add(configuration);
    return configuration;
}

private void EnsureChannelIsFree(NotificationChannel channel, Guid? exceptId = null)
{
    var occupied = _configurations.Any(c =>
        c.IsEnabled && c.Channel == channel && c.Id != exceptId);

    if (occupied)
        throw new DomainException(
            $"Ya existe una configuración activa para el canal {channel}.");
}
```

<Callout kind="concepto" title="Por qué NotificationConfiguration no es su propio agregado">

`NotificationConfiguration` no tiene sentido de negocio fuera de un `NotificationTrigger` — no existe "una configuración huérfana". Por eso vive como entidad hija dentro del agregado, con métodos `internal` (`Enable`, `Disable`, `ChangeTemplate`) para que solo la raíz pueda invocarlos. Nadie fuera de `NotificationTrigger.cs` puede violar la invariante de canal único ni por accidente — el compilador lo impide.

</Callout>

```csharp title="Domain/Triggers/NotificationConfiguration.cs (completo)"
public class NotificationConfiguration : Entity
{
    public Guid TemplateId { get; private set; }
    public NotificationChannel Channel { get; private set; }
    public bool IsEnabled { get; private set; }

    internal static NotificationConfiguration Create(Guid templateId, NotificationChannel channel)
    {
        if (templateId == Guid.Empty)
            throw new DomainException("La configuración requiere una plantilla.");
        // ...
        return new NotificationConfiguration { Id = Guid.NewGuid(), TemplateId = templateId,
            Channel = channel, IsEnabled = true };
    }

    internal void Enable() => IsEnabled = true;
    internal void Disable() => IsEnabled = false;
    internal void ChangeTemplate(Guid templateId) { /* ... */ TemplateId = templateId; }
}
```

### Value objects que no se pueden saltar

`EventKey` y `TemplateName` son `record` con constructor privado: la única forma de obtener una instancia es `Create(...)`, que valida formato con regex (`dominio.accion` para el primero, `snake_case` para el segundo) antes de dejar existir el objeto. Un `string` mal formado nunca llega a persistirse.

```csharp title="Domain/Triggers/EventKey.cs (completo)"
public sealed record EventKey
{
    public const int MaxLength = 200;

    private static readonly Regex Format = new(@"^[a-z0-9]+(\.[a-z0-9]+)+$", RegexOptions.Compiled);

    public string Value { get; }
    private EventKey(string value) => Value = value;

    public static EventKey Create(string value)
    {
        if (string.IsNullOrWhiteSpace(value))
            throw new DomainException("El event key es obligatorio.");

        var normalized = value.Trim().ToLowerInvariant();

        if (!Format.IsMatch(normalized))
            throw new DomainException($"El event key '{value}' debe tener el formato dominio.accion.");

        return new EventKey(normalized);
    }
}
```

### Igualdad por identidad, no por valores

`Entity` — la base de todos los agregados — sobreescribe `Equals` para comparar por `Id` y tipo concreto, nunca por el contenido de las propiedades. Dos entidades sin persistir (`Id == Guid.Empty`) nunca son iguales entre sí, ni siquiera a sí mismas comparadas dos veces: evita que dos triggers recién creados y aún no guardados colisionen en un `HashSet`.

```csharp title="Domain/Common/Entity.cs (completo)"
public override bool Equals(object? obj)
{
    if (obj is not Entity other) return false;
    if (ReferenceEquals(this, other)) return true;
    if (GetType() != other.GetType()) return false;

    // Dos entidades sin persistir nunca son iguales entre sí
    if (Id == Guid.Empty || other.Id == Guid.Empty) return false;

    return Id == other.Id;
}
```

### Domain events: el mecanismo ya existe, nadie lo usa todavía

<Callout kind="honesto" title="AggregateRoot expone Raise(), pero ningún agregado lo llama">

`AggregateRoot` ya tiene `DomainEvents`, `Raise(IDomainEvent)` y `ClearDomainEvents()` listos. Es exactamente el mismo hallazgo que el [módulo 10 del tutorial de DDD](/ddd/domain-events) documenta en detalle: el mecanismo está construido, pero ningún agregado de este repositorio llama a `Raise` todavía. Un candidato natural para el primer evento real sería `NotificationTrigger.AddConfiguration` — verás exactamente cómo se vería en la [página de tareas guiadas](/ddd/tareas).

</Callout>

```csharp title="Domain/Common/AggregateRoot.cs (completo)"
public abstract class AggregateRoot : Entity
{
    private readonly List<IDomainEvent> _domainEvents = new();

    public IReadOnlyCollection<IDomainEvent> DomainEvents => _domainEvents.AsReadOnly();

    protected void Raise(IDomainEvent domainEvent) => _domainEvents.Add(domainEvent);

    public void ClearDomainEvents() => _domainEvents.Clear();
}
// Ningún agregado (NotificationTrigger, NotificationTemplate, Recipient, Notification) llama
// a Raise() todavía — el mecanismo existe, esperando su primer evento real.
```

### Constantes de longitud: viven en el dominio, no en la base de datos

`Recipient.NameMaxLength`, `Notification.ErrorMaxLength`, `TemplateVersion.BodyMaxLength` — cada límite de tamaño es una constante pública en la clase del dominio que lo posee. FluentValidation (en Application) y la configuración de EF Core (en Infrastructure) las reutilizan en vez de repetir el número mágico en tres sitios distintos. Cambiar un límite es cambiar una línea, no perseguir tres archivos.
