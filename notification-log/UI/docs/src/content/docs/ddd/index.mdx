Se puede aprender DDD con el ejemplo del carrito de compras, o se puede aprender abriendo `NotificationLog.NotificationService.Domain` y viendo **por qué** una clase se llama `EventKey` y no `string key`, o **por qué** `NotificationTrigger` rechaza una configuración duplicada antes de que llegue a la base de datos.

Este tutorial elige la segunda opción: cada concepto se enseña señalando un archivo real de este repositorio, con su ruta completa, para que puedas abrirlo y comprobar por ti mismo que la explicación es cierta.

<Callout kind="honesto" title="Los fragmentos de código no están copiados a mano">

Cada bloque de código de estas páginas se **importa del archivo `.cs` real** en tiempo de compilación, recortado por firma de método o por anclas de texto. Si alguien renombra un método, la documentación no se queda desactualizada en silencio: falla la compilación del sitio.

Por eso puedes confiar en que lo que lees aquí es lo que hay en el repositorio hoy.

</Callout>

Cuando el código todavía no cubre un patrón —por ejemplo, un dominio que no levanta ningún evento— este tutorial te lo dice de frente, en vez de inventar un ejemplo. Esa honestidad es parte de la lección: un sistema real con DDD bien aplicado no se ve como la foto perfecta de un libro, se ve como este repositorio, con partes maduras y partes en construcción.

## De qué va el sistema

Notifications escucha hechos de negocio publicados por otros sistemas —"un usuario se registró", "una publicación se aprobó"— y decide, según una configuración declarativa propia, si eso dispara una notificación, con qué texto y por qué canal.

Esa separación —*quien produce el hecho no sabe nada de plantillas ni de canales; quien notifica no sabe nada del negocio que originó el hecho*— es el hilo que conecta las cuatro partes de este tutorial.

## Cómo está organizado

El temario avanza de lo **estratégico** (decisiones sobre el negocio, antes de escribir una clase) a lo **táctico** (cómo se modela dentro de una frontera ya decidida), sigue con la **arquitectura** que sostiene el modelo, y termina en **práctica**: tareas reales para modificar este mismo código.

## Temario completo

Catorce módulos, cada uno con un objetivo concreto y al menos un archivo real que lo demuestra. Sigue el orden con los botones "Siguiente", o salta al tema que te interese.

| # | Módulo | Vas a aprender a... | Archivo ancla |
| --- | --- | --- | --- |

| 2 | [Subdominios y Core Domain](/ddd/subdominios) | Decidir dónde vale la pena invertir en modelado táctico completo y dónde no. | `Application/.../Dispatch/BusinessEvent.cs` |

<Callout kind="concepto" title="Cómo leer cada página">

Todas las páginas tienen la misma estructura, para que puedas estudiarlas en cualquier orden:

1. **Objetivos del módulo** — qué vas a poder hacer al terminar.
2. **En una frase** — la idea completa, resumida, antes de los detalles.
3. **Concepto** — la definición general, la que encontrarías en cualquier libro.
4. **El código real** — importado del repositorio, con su ruta exacta.
5. **Para recordar** — los cuatro o cinco puntos que valen para el examen.
6. **Comprueba que lo entendiste** — preguntas para responder sin mirar el código.

Y siete tipos de recuadro, siempre con el mismo significado:

| | Significado |
| --- | --- |
| 💡 **concepto** | La definición general del patrón. |
| 🧩 **código real** | Extraído tal cual del repositorio. |
| ⚠️ **advertencia** | Un matiz o un error común al aplicar el patrón. |
| 🚫 **antipatrón** | Una forma concreta de hacerlo mal, con su ejemplo. |
| ✏️ **ejercicio** | Algo para pensar o para escribir. |
| 🔍 **honesto** | Qué parte del patrón todavía no está implementada, o una decisión real del equipo. |
| 📌 **resumen** | Lo que hay que llevarse de la página. |

</Callout>
