Se puede aprender DDD con el ejemplo del carrito de compras, o se puede aprender abriendo `NotificationLog.NotificationService.Domain` y viendo por qué una clase se llama `EventKey` y no `string key`, o por qué `NotificationTrigger` rechaza una configuración duplicada antes de que llegue a la base de datos. Este tutorial elige la segunda opción: cada concepto se enseña señalando un archivo real de este repositorio, con su ruta completa, para que puedas abrirlo y comprobar por ti mismo que la explicación es cierta.

Cuando el código todavía no cubre un patrón — por ejemplo, el mecanismo de eventos de dominio existe pero nadie lo usa todavía — este tutorial te lo dice de frente, en vez de inventar un ejemplo que no existe. Esa honestidad es, en sí misma, parte de la lección: un sistema real con DDD bien aplicado no se ve como la foto perfecta de un libro, se ve como este repositorio, con partes maduras y partes en construcción.

NotificationLog es un servicio que escucha hechos de negocio publicados por otros sistemas — por ejemplo, "un usuario verificó su email" — y decide, según una configuración declarativa propia, si eso dispara una notificación, con qué texto y por qué canal. Esa separación — *quien produce el hecho no sabe nada de plantillas ni de canales; quien notifica no sabe nada del negocio que originó el hecho* — es el hilo que conecta las cuatro secciones de este tutorial: primero el vocabulario y las fronteras del negocio, después cómo se protege ese negocio dentro del código, y por último la arquitectura y los ejercicios para practicar sobre el propio repositorio.

## Cómo está organizado

El temario avanza de lo estratégico (decisiones sobre el negocio, antes de escribir una sola clase) a lo táctico (cómo se modela dentro de una frontera ya decidida) y termina en la arquitectura que sostiene todo eso en producción. La última sección no enseña un concepto nuevo: es una lista de tareas reales para modificar este mismo código y comprobar, con las manos, que entendiste el resto.

<Callout kind="honesto" title="Cómo leer cada página">

Vas a encontrar seis tipos de recuadro, siempre con el mismo significado: **concepto** (la definición general, la que encontrarías en cualquier libro de DDD), **código real** (extraído tal cual de este repositorio, con su ruta exacta), **advertencia** (un matiz o un error común al aplicar el patrón), **antipatrón** (una forma concreta de hacerlo mal), **ejercicio** (algo para pensar antes de seguir) y **honesto** (una nota que marca qué parte del patrón todavía no está implementada en este código, o una decisión de diseño real del equipo). La idea es que nunca tengas que confiar en la palabra de esta guía: cada afirmación se puede verificar abriendo el archivo señalado.

</Callout>
