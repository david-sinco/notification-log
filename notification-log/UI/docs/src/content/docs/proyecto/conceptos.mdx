## Trigger: "cuando pasa X, revisa qué hacer"

Un **trigger** representa un hecho de negocio que le importa a Notifications — "un pedido se confirmó", "un usuario verificó su email". Se identifica con un *event key* con formato `dominio.accion` (`pedido.confirmado`), tiene una descripción legible y un interruptor general: habilitado o deshabilitado. Deshabilitar un trigger apaga todas sus notificaciones de un golpe, sin borrar la configuración.

### Configuración: el canal dentro de un trigger

Cada trigger puede tener varias **configuraciones**, una por canal (Email, SMS, Push, WhatsApp). Cada configuración apunta a una plantilla concreta. La única regla dura del sistema: un mismo trigger no puede tener dos configuraciones activas para el mismo canal — no tiene sentido enviar dos emails distintos por el mismo hecho. Una configuración se puede deshabilitar sin borrarla (por ejemplo, para pausar el canal SMS de un trigger sin perder a qué plantilla apuntaba).

<Callout kind="concepto" title="Un ejemplo completo">

Trigger `pedido.confirmado` → configuración de canal **Email** apuntando a la plantilla `confirmacion_compra`, y otra configuración de canal **SMS** apuntando a `confirmacion_compra_sms`. Cuando llega el hecho "pedido confirmado" para un destinatario, ambas configuraciones activas se procesan — ese destinatario recibe, potencialmente, un email y un SMS por el mismo evento.

</Callout>

## Plantilla: el contenido, versionado

Una **plantilla** tiene un nombre (`snake_case`, como `confirmacion_compra`), pertenece a un solo canal, y guarda un historial de **versiones**: cada publicación nueva (`PublishVersion`) retira la versión anterior y la reemplaza como "vigente", sin borrar el historial. Solo Email y Push exigen asunto; SMS y WhatsApp no lo admiten — es una regla que vive en el propio dominio (`TemplateVersion.NormalizeSubject`), no una validación aparte del formulario.

El cuerpo de una plantilla puede usar los datos del destinatario que la recibe (`recipient.name`, `recipient.email`, `recipient.phone`, `recipient.locale`, `recipient.timeZone`, más cualquier atributo propio del destinatario) y los campos que traiga el propio evento de negocio — el panel de creación de plantillas muestra exactamente esa lista de datos disponibles al escribir el contenido.

## Destinatario: a quién le puede llegar algo

Un **destinatario** (`Recipient`) es un perfil delgado: nombre, email, teléfono, idioma, zona horaria, un estado activo/inactivo, y atributos libres clave-valor para lo que un negocio concreto necesite (por ejemplo, `plan: premium`). No es "el usuario completo" del sistema que lo originó — es solo lo que este proyecto necesita para decidir a dónde y en qué idioma enviar algo. Un destinatario "puede recibir" por un canal solo si está activo y tiene el dato de contacto de ese canal (email para Email, teléfono para SMS/WhatsApp).

## Notificación: el registro de lo que pasó

Una **notificación** es el resultado de un intento de envío — nunca se crea "antes" de intentar enviar, siempre después, ya sea con éxito o con fallo. Guarda el canal, el destino real usado, el evento que la originó, la plantilla y versión exactas que se usaron, y si falló, el motivo del error. Es la vista de auditoría: "¿a quién le llegó qué, cuándo, y si algo falló, por qué".
